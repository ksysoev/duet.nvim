1. INTRODUCTION                                     *duet* *duet-introduction*

duet.nvim runs an AI coding agent in a Neovim terminal, lets the agent drive
the editor through an MCP server, and adds a diff/document review loop with
line annotations.

This plugin is a work in progress. See the roadmap:
https://github.com/ksysoev/duet.nvim/issues/1

Requires Neovim >= 0.11. duet has no plugin dependencies.

==============================================================================
2. SETUP                                                          *duet-setup*

Calling `setup()` is optional: without it, the defaults apply. Nothing is
loaded at startup; modules load the first time you use duet.

With lazy.nvim: >lua
    { "ksysoev/duet.nvim", opts = {} }
<
Or directly: >lua
    require("duet").setup({ log_level = "info" })
<
`setup()` can be called again; each call starts from the defaults, so options
from an earlier call do not stick. If the options are invalid, an error is
shown and the previous configuration stays in effect. Unknown options produce
a single warning listing them.

3. CONFIGURATION                                                 *duet-config*

Defaults: >lua
    {
      log_level = "warn",
      agent = "claude",
      agents = {},
      terminal = {
        layout = "right",
        float = { width = 0.9, height = 0.9, border = "rounded" },
        split = { width = 80, height = 0.4 },
        close_on_exit = "success",
        auto_insert = true,
        keys = {
          ["<C-q>"] = "normal_mode",
          gf = "open_link",
          ["<CR>"] = "open_link",
          ["]l"] = "next_link",
          ["[l"] = "prev_link",
          ["<C-LeftMouse>"] = "open_link_mouse",
        },
      },
      links = { highlight = false, debounce_ms = 100 },
      send = { submit_delay_ms = 100, ready_timeout_ms = 10000 },
      prompts = {
        explain = "Explain {this}",
        fix = "Fix {diagnostics}",
        review = "Review {file}",
      },
      review = {},
    }
<
Tables merge deeply with the defaults. Lists (such as a command line) replace
the default list instead of merging into it.

                                                       *duet-config-log_level*
log_level ~
    `string|integer` (default: `"warn"`)
    Minimum level written to the log file |duet-log|. One of `"trace"`,
    `"debug"`, `"info"`, `"warn"`, `"error"`, `"off"`, or a |vim.log.levels|
    number. Overridden by the `$DUET_LOG_LEVEL` environment variable.

                                                           *duet-config-agent*
agent ~
    `string` (default: `"claude"`)
    Name of the agent adapter used by default.

                                                          *duet-config-agents*
agents ~
    `table<string, table>` (default: `{}`)
    Per-agent overrides, keyed by agent name. Each entry may set:

                                                     *duet-config-agents-cmd*
    cmd ~
        `string[]`: the command line, replacing the adapter's (for
        Claude Code, `{ "claude" }`). Use it to point at a binary that is not
        on your PATH, or to wrap the agent.
                                                    *duet-config-agents-args*
    args ~
        `string[]`: extra arguments, added after `cmd` and before the
        arguments duet adds.
                                                     *duet-config-agents-env*
    env ~
        `table<string, string>`: extra environment variables for the agent.
        They take precedence over variables duet sets.

    Example: >lua
        agents = {
          claude = {
            cmd = { "/opt/claude/bin/claude" },
            args = { "--model", "opus" },
            env = { DISABLE_AUTOUPDATER = "1" },
          },
        }
<
    Other keys inside an entry are not reported as unknown, so adapters can
    read their own options.

                                                        *duet-config-terminal*
terminal ~
    `table`
    Agent terminal options. See |duet-terminal|.

    Sizes below are a fraction of the editor when `<= 1`, otherwise a number
    of columns or lines.

                                                 *duet-config-terminal-layout*
    layout ~
        `string` (default: `"right"`)
        Where the terminal opens: `"right"`, `"left"` (full-height vertical
        splits at the edge of the editor, with 'winfixwidth'), `"bottom"`
        (full-width horizontal split, with 'winfixheight') or `"float"`.
        A side panel keeps the code you talk about in view.
                                                  *duet-config-terminal-float*
    float ~
        `{ width, height, border }` (default:
        `{ width = 0.9, height = 0.9, border = "rounded" }`)
        Size and border of the float, which is centred in the editor.
        `border` takes the values of the `border` key of
        |nvim_open_win()|: a name, or a list of 1, 2, 4 or 8 strings. An
        unknown name is reported when the terminal opens.
                                                  *duet-config-terminal-split*
    split ~
        `{ width, height, min_code_width, min_code_height }` (default:
        `{ width = 80, height = 0.4,`
          `min_code_width = 20, min_code_height = 5 }`)
        Width of the `"right"` and `"left"` splits, height of the `"bottom"`
        split. A fractional size is applied again when the editor is
        resized.

        An absolute size is capped so the rest of the editor keeps
        `min_code_width` columns (`min_code_height` lines for `"bottom"`),
        plus the separator. On an 80-column editor the default panel is 59
        columns wide and the code gets 20. On an editor narrower than twice
        the minimum plus one (41 columns with the defaults), the split and
        the rest share it evenly, the rest getting any odd column, so a
        30-column editor gives the panel 14 columns and the code 15. Moving
        into the code window then lets Neovim widen it to 'winwidth', taking
        columns from the panel; the panel grows back when the editor does.
        Fractional sizes are not capped.

        The cap is applied when the split opens, when it replaces another
        session's split, when the editor is resized, and when the room for
        windows changes in the current tab page: the tabline, the command
        line ('cmdheight') or the status line ('laststatus') take more or
        fewer lines, e.g. when a second tab page shows the tabline. A split
        that no longer leaves that room shrinks, and grows back toward its
        size when there is room again. A split in another tab page is sized
        when you enter it. If you resize the split by hand, that size is the
        one it keeps, shrinks from and grows back to, until the split is
        closed or `setup()` changes `width` or `height`. Any other change to
        its size counts as yours, except one that comes with a change in the
        room: dragging the last status line to resize the command line
        leaves the split's size alone. A change made in the same instant as
        a change in the room or as moving to another window, e.g. by a
        script, is not noticed.

        Set a minimum to `0` to leave only what 'winminwidth' and
        'winminheight' require, which Neovim always keeps. Only the editor's
        size is counted: other windows beside the code, such as a file tree
        with 'winfixwidth', are not taken off the room the code keeps.
                                          *duet-config-terminal-close_on_exit*
    close_on_exit ~
        `string` (default: `"success"`)
        What happens to the terminal when the agent exits:
        - `"success"`: close its window and wipe its buffer when the agent
          exits with code 0. After any other code the terminal stays, so
          you can read the agent's last output.
        - `"always"`: close it whatever the exit code.
        - `"never"`: keep it whatever the exit code.
        A non-zero exit is reported as an error either way. See
        |duet-terminal-exit|.
                                            *duet-config-terminal-auto_insert*
    auto_insert ~
        `boolean` (default: `true`)
        Enter |Terminal-mode| when the terminal is opened or entered.
                                                   *duet-config-terminal-keys*
    keys ~
        `table<string, string|false>` (default: `<C-q>` leaves
        terminal mode, `gf` and `<CR>` open a link, `]l` and `[l` move
        between links, CTRL-click opens the link clicked)
        Buffer-local mappings in the terminal, keyed by {lhs}. Your keys
        are added to the defaults, and replace a default for the same key
        however it is spelled (`<cr>` replaces `<CR>`). Actions:
        - `"normal_mode"`: leave |Terminal-mode| (terminal mode only).
        - `"hide"`: hide the terminal (terminal and normal mode).
        - `"open_link"`: open the file link under the cursor (normal
          mode). See |duet-links|. Mapped to <CR>, it moves the cursor down
          as usual where there is no reference to open.
        - `"open_link_mouse"`: open the file link clicked (terminal and
          normal mode). Bind it to a mouse key such as `<C-LeftMouse>`:
          it reads where the mouse is, and a key such as `gf` would no
          longer reach the agent in terminal mode. See
          |duet-links-mouse|.
        - `"next_link"`, `"prev_link"`: move to the next or previous file
          link in the visible output; a count repeats it (normal mode).
          The defaults `]l` and `[l` replace Neovim's |]l| and |[l| in the
          agent's terminal only.
        - `false`: no mapping, e.g. to turn off a default.

                                                           *duet-config-links*
links ~
    `table`
    File links in the agent's output. See |duet-links|.
                                                 *duet-config-links-highlight*
    highlight ~
        `boolean` (default: `false`)
        Underline the links in the visible part of the terminal that point
        to existing files, with |hl-DuetLink|. Each update checks the
        files on screen, so it is off by default. Read when a terminal
        starts.
                                               *duet-config-links-debounce_ms*
    debounce_ms ~
        `integer` (default: `100`)
        With `highlight`, how often, at most, the links are underlined
        again while output changes or the window scrolls, in milliseconds.
        They are also underlined once it stops.
                                         *duet-config-links-replace_filetypes*
    replace_filetypes ~
        `string[]` (default: `{ "snacks_dashboard", "alpha", "dashboard",`
        `"ministarter", "startify" }`)
        Filetypes of start screens that a file link opens in place of, when
        no window shows a file, instead of opening a split. See
        |duet-links|. An empty list turns this off.

                                                           *duet-config-watch*
watch ~
    `table`
    Reloading buffers when the agent changes their files. See |duet-watch|.
                                                   *duet-config-watch-enabled*
    enabled ~
        `boolean` (default: `true`)
        Watch the directories of listed file buffers while an agent session
        runs. Read when a session starts or stops.
                                               *duet-config-watch-debounce_ms*
    debounce_ms ~
        `integer` (default: `100`)
        How long to wait after the last change on disk before checking the
        buffers, in milliseconds, so a burst of writes is checked once.
        Changes that keep coming, such as a log written all the time, delay
        the check by at most a second (or `debounce_ms`, if longer).
                                                  *duet-config-watch-autoread*
    autoread ~
        `boolean` (default: `true`)
        Turn on the global 'autoread' while watching, so unchanged buffers
        reload without asking. Its previous value comes back when the last
        session stops, unless you set it meanwhile. With `false`,
        'autoread' is left as it is.

                                                            *duet-config-send*
send ~
    `table`
    How text is sent to the agent. See |duet-send|.
                                            *duet-config-send-submit_delay_ms*
    submit_delay_ms ~
        `integer` (default: `100`)
        Milliseconds to wait after the end of a paste before pressing
        <Enter>, so the agent has taken the paste in. Raise it if long
        pastes are left in the agent's input without being submitted.
                                           *duet-config-send-ready_timeout_ms*
    ready_timeout_ms ~
        `integer` (default: `10000`)
        How long, in milliseconds, a send waits for the agent to be ready
        for input: started, with its input prompt on screen rather than a
        dialog. After that the send fails. See |duet-send|.

                                                         *duet-config-prompts*
prompts ~
    `table<string, string|false>`
    Prompt templates for |:Duet-ask| and |duet.ask()|, by name: letters,
    digits, `_` and `-`, since `:Duet ask` takes it as one word. A template
    is text with placeholders such as `{this}` (see |duet-context|). Your
    prompts are added to the defaults; set a default to `false` to remove
    it: >lua
        prompts = {
          tests = "Write tests for {this}",
          review = false,
        }
<
                                                          *duet-config-review*
review ~
    `table` (default: `{}`)
    Review options. Filled in by upcoming features.

4. COMMANDS                                               *duet-commands* *:Duet*

:[range]Duet[!] {subcommand} [args]
    Run a duet subcommand. The range and `!` are passed to the subcommand.
    <Tab> completes subcommand names and, where supported, their arguments.

:Duet                                                          *:Duet-toggle*
:Duet toggle [{agent}]
    Toggle the agent terminal for the current project: hide it if it is shown
    in the current tab, otherwise open it (see |:Duet-open|). Without
    {agent}, acts on the shown session, else the current one
    (|duet.terminal.current()|), else starts |duet-config-agent|.

:Duet open [{agent}]                                             *:Duet-open*
    Show the agent terminal and move the cursor into it. Starts the agent if
    it is not running for this project. An agent that has exited is
    restarted, except that a terminal you have not seen since the agent
    exited is shown first (see |duet-terminal-exit|).

:Duet close [{agent}]                                           *:Duet-close*
:Duet! close [{agent}]
    Hide the agent terminal; the agent keeps running. With `!`, stop the
    agent and wipe its terminal buffer. Without {agent}, acts on the shown
    session, else the current one.

:Duet restart [{agent}]                                       *:Duet-restart*
    Stop the agent and start it again, in the same window if it is shown.
    Starts it if it is not running.

:[range]Duet send {text}                                          *:Duet-send*
:[range]Duet! send {text}
    Send {text} to the agent of the current project and submit it, as if
    you had pasted it and pressed <Enter>. {text} is taken as typed,
    spaces included, except that placeholders such as `{file}` or
    `{selection}` are replaced with editor context (see |duet-context|);
    [range] is the lines they use. With `!`, only paste it, so you can
    edit it in the agent before you submit it. Starts the agent if it is
    not running. See |duet-send|. >vim
        :'<,'>Duet send Refactor {selection}
<
:[range]Duet prompt [{text}]                                    *:Duet-prompt*
:[range]Duet! prompt [{text}]
    Ask for a prompt with |vim.ui.input()|, prefilled with {text}, and send
    it like |:Duet-send|, placeholders included. Cancelling, or an empty
    prompt, sends nothing.

:[range]Duet ask [{name}]                                          *:Duet-ask*
:[range]Duet! ask [{name}]
    Send the prompt template {name} from |duet-config-prompts|, with its
    placeholders replaced (see |duet-context|). Without {name}, pick one
    with |vim.ui.select()|. <Tab> completes the names. With `!`, only
    paste it. >vim
        :Duet ask explain
        :'<,'>Duet ask fix
<

5. HEALTH                                                        *duet-health*

Run `:checkhealth duet` to check:
- the Neovim version (>= 0.11 is required),
- that `git` is on your PATH (needed for reviews),
- your configuration (invalid values and unknown options),
- the location of the log file,
- that 'mouse' lets the terminal get clicks when a key opens links with one,
  and that such a key is a mouse click
  (|duet-links-mouse|),
- for the default agent and every agent under |duet-config-agents|: that
  its command can be found (on your PATH, or at the path you set) and
  which file it resolves to, its version (for Claude Code, from
  `claude --version`), and which duet features it does not support.

6. LOG FILE                                                         *duet-log*

7. LUA API                                                          *duet-api*

require("duet").setup({opts})                                  *duet.setup()*
    Configure duet. See |duet-setup|. Returns `true`, or `nil` and an error
    message when the options are invalid.

require("duet").toggle([{agent}])                             *duet.toggle()*
require("duet").open([{agent}])                                 *duet.open()*
require("duet").close([{opts}])                                *duet.close()*
    Same as |:Duet-toggle|, |:Duet-open| and |:Duet-close|. {opts} may set
    `stop = true` (like `:Duet! close`) and `agent`. `toggle` and `open`
    return the session, or `nil` and an error message.

require("duet").send({text} [, {opts}])                          *duet.send()*
    Send {text} to the agent as one paste and submit it. See |duet-send|.
    {opts} is a table with:
    - `submit`   `boolean` (default: `true`): press <Enter> after the
                 paste. `false` only pastes.
    - `focus`    `boolean` (default: `false`): move the cursor into the
                 agent's terminal.
    - `agent`    `string`: the agent to send to (default: the current
                 session's agent, else |duet-config-agent|).
    - `session`  a session (see |duet.terminal.current()|) to send to
                 instead. It must be running.
    - `on_done`  `fun(err?: string)`: called once the text has been
                 written to the agent, or with an error message if it
                 could not be. Without it, such errors are shown.
    Returns `true` once the text is queued, or `nil` and an error message
    (for example for empty text, or when the agent cannot start); `on_done`
    is not called then. `on_done` is always called after `send()` has
    returned.

require("duet").ask({name} [, {opts}])                            *duet.ask()*
    Send prompt template {name}, like |:Duet-ask|, with the context of the
    current window. Called from visual mode (a mapping), the selection is
    the range, and visual mode ends. {opts} may set `submit = false` (only
    paste) and `agent`. Returns `true` once the text is queued, or `nil` and
    an error message, e.g. for an unknown prompt or when every placeholder
    is empty.

require("duet").render({template})                             *duet.render()*
    Replace the placeholders in {template} with the current context, as
    |:Duet-send| does, without sending anything. Returns the text and a
    table with `used` (the placeholders found), `empty` (those that had
    nothing to add, failed ones included) and `errors` (why a placeholder
    failed, by name).

require("duet.context").register({name}, {fn})     *duet.context.register()*
    Add a placeholder `{name}` (letters, digits and `_`), or replace one,
    built-ins included. {fn} gets the context (see |duet-context-ctx|) and
    returns `{ text = string, data = table, block? = boolean }`, or `nil`
    when it has nothing to add. `text` is what the agent reads; `data` is
    the same information as plain values, for tools; `block = true` puts
    multi-line text on lines of its own. >lua
        require("duet.context").register("branch", function(ctx)
          local out = vim.system({ "git", "branch", "--show-current" },
            { cwd = ctx.cwd, text = true }):wait()
          local name = vim.trim(out.stdout or "")
          if name ~= "" then
            return { text = name, data = { branch = name } }
          end
        end)
<
    Providers run on the main loop while the command runs, so keep them
    quick.

require("duet.context").unregister({name})       *duet.context.unregister()*
    Remove a placeholder. Removing one you registered over a built-in
    brings the built-in back; removing a built-in itself hides it, and
    `{name}` is then sent as typed.

require("duet.config").get()                              *duet.config.get()*
    Return the current configuration (treat it as read-only).

require("duet.commands").register({name}, {spec})   *duet.commands.register()*
    Add a `:Duet` subcommand. {spec} is a table with:
    - `impl`     `fun(args: string[], opts: table)`: runs the subcommand.
                 `opts` are the |nvim_create_user_command()| callback
                 arguments plus `opts.rest`, the raw text after the
                 subcommand name. May return `nil, err` to show an error.
    - `complete` `fun(arglead: string, args: string[]): string[]`
                 (optional): completes the argument being typed. `args` are
                 the words typed before it, after the subcommand name.
    - `desc`     `string` (optional): one-line description.
    Registering an existing name replaces it.

require("duet.commands").unregister({name})       *duet.commands.unregister()*
    Remove a `:Duet` subcommand, built-in ones included.

require("duet.health").register({name}, {fn})         *duet.health.register()*
    Add a section to `:checkhealth duet`. {fn} reports with |vim.health|
    functions. A check that throws is shown as an error without hiding the
    others.

require("duet.agents").get({name})                       *duet.agents.get()*
    Return the adapter {name} (default: |duet-config-agent|) with the
    overrides from |duet-config-agents| applied, or `nil` and an error
    message when there is no such adapter. Each call returns a new instance.

require("duet.agents").list()                           *duet.agents.list()*
    Return the names of all adapters, sorted.

require("duet.agents").register({adapter})          *duet.agents.register()*
    Add an adapter, or replace one with the same name. See
    |duet-agents-adapter|.

8. AGENTS                                                        *duet-agents*

duet runs agents through adapters. An adapter knows the agent's command line
and how to give it duet's MCP server, hooks and system prompt. The rest of
duet only talks to adapters. Built-in adapters:

  `claude`  Claude Code (https://code.claude.com). Supports the MCP server,
            plan review and the system prompt.

duet never changes an agent's own configuration files. For Claude Code, it
writes a per-session `mcp.json` and `settings.json` and passes them with
`--mcp-config` and `--settings`. Claude Code merges those with your own
settings, so hooks you configured yourself (for example another
`ExitPlanMode` hook) still run.

Writing an adapter                                       *duet-agents-adapter*

An adapter is a table: >lua
    require("duet.agents").register({
      name = "myagent",
      cmd = { "myagent" },
      capabilities = { mcp = true, plan_hook = false, system_prompt = false },
      launch = function(self, spec)
        local argv = vim.list_extend(vim.deepcopy(self.cmd), self.args)
        return { argv = argv, env = self.env, files = {} }
      end,
    })
<
Fields:
- `name`          `string`
- `cmd`           `string[]`: the command line before any added arguments.
- `capabilities`  `{ mcp, plan_hook, system_prompt }`, all `boolean`. duet
                  turns off features whose capability is `false`.
- `launch`        `fun(self, spec): plan`. Must be pure: no files written,
                  no processes started. `self.cmd`, `self.args` and
                  `self.env` already include the user's overrides.
- `is_ready`      (optional) `fun(self, lines): boolean`: whether the
                  agent's terminal (given as its last lines) accepts input:
                  `false` while the agent starts up or shows a dialog, such
                  as a permission prompt. Without it, duet sends text as
                  soon as the agent runs and can't tell when it is asking
                  something, so define it for any agent with a TUI.
- `read_input`    (optional) `fun(self, lines): string|nil`: the agent's
                  input box as shown in its terminal (given as its last
                  lines), or `nil` if no input box is on screen. It can be
                  the box's raw lines, placeholder included: duet compares
                  it from one moment to the next, and checks whether it
                  ends with a one-line text of up to 200 bytes (whitespace
                  and no-break spaces ignored, so wrapped rows are fine).
                  With it, a send presses <Enter> once the paste shows in
                  the box, and the next send waits until <Enter> has been
                  taken in (the box changed and no longer shows the text),
                  so two sends can't merge into one message (see
                  |duet-send|).
- `format_ref`    (optional) `fun(self, path, range?): string`: how to
                  refer to a file in a prompt (|duet-context|). `path` is
                  relative to the project; `range` is `{ first, last }`
                  (equal for one line). Without it, duet writes `path`,
                  `path:L10` or `path:L10-L20`. Claude Code's adapter
                  writes `@path`, `@path (line 10)` or
                  `@path (lines 10-20)`, so Claude Code reads the file. A
                  path with spaces is written without the `@`, since an
                  `@` mention ends at the first space.
- `health`        (optional) `fun(self)`: extra |vim.health| reports, such
                  as the version.

`spec` (a `duet.LaunchSpec`) has `cwd`, `session_id`, `run_dir` (the
per-session directory), and optionally `mcp` (`{ name, command, env }`),
`hooks.plan_review` (`{ command, timeout_s? }`), `system_prompt` and
`tool_timeout_ms`.

The returned plan (a `duet.LaunchPlan`) has `argv`, `env`, and `files`, a
list of `{ path, content }`. duet writes the files with mode 0600 before it
starts the agent. Every path must be inside `spec.run_dir`.

9. TERMINAL                                                    *duet-terminal*

duet runs the agent CLI in a Neovim |terminal|, one session per agent and
project. The project is the git root of the current directory (|getcwd()|),
or the directory itself outside a repository; the agent runs there. Hiding
the terminal keeps the agent running, so reopening it shows the same
conversation.

Each session gets a private directory, `stdpath("run")/duet/<id>/` (mode
0700), for the files its adapter asks for (mode 0600), such as the MCP
config. It is removed when the agent exits, and every agent is stopped when
Neovim exits. The agent's environment has `$NVIM` set to |v:servername|; if
Neovim has no server yet (for example with `--headless`), duet starts one.

                                                          *duet-terminal-exit*
When the agent exits with code 0 (for example after CTRL-D), its terminal
closes and the session ends; the next |:Duet| starts a new one. When it
exits with another code, the terminal stays with the agent's last output and
duet shows an error with the exit code, its reason and the last few lines of
output. The reason names the signal for codes above 128 (e.g. `137` is
"killed (SIGKILL)"), and code 127 means "command not found".
|duet-config-terminal-close_on_exit| changes which exits close the terminal.

In a terminal kept after the agent exited, `i`, `a`, `I` or `A` restarts the
agent in the same window, and `q` closes the terminal and ends the session.
A key you map in Normal mode in |duet-config-terminal-keys| (any action but
`"normal_mode"`) keeps that action, and the error message only names the keys
that are left.

If the agent exits while its terminal is hidden and the terminal is kept,
|:Duet-open| (or |:Duet|) first shows it, so you can read the output; opening
it again starts a new session. Exits caused by duet (|:Duet-close| with `!`,
|:Duet-restart|, wiping the buffer, quitting Neovim) are not reported.

Terminal buffers have the filetype `duet_terminal`, a name of the form
`duet://<agent>/<id>`, and `b:duet_session` set to the session id. Only one
duet terminal is shown per tab page: opening another hides the first.

require("duet.terminal").current()                  *duet.terminal.current()*
    Return the session for the current context, or `nil`: the session of
    the current buffer, else the most recently used session for the current
    project. Never starts a session. A session has `id`, `agent`, `root`,
    `buf`, `job` (`nil` once exited), `exit_code` (set once exited) and the
    methods `show()`, `hide()`, `focus()`, `toggle()`, `restart()`, `stop()`
    and `is_visible()`.

require("duet.terminal").target([{agent}])            *duet.terminal.target()*
    Return the session that commands such as |:Duet-send| act on, or `nil`:
    {agent}'s session for the current project, or without {agent} the
    session shown in the current tab, else |duet.terminal.current()|. Never
    starts a session.

require("duet.terminal").get({id})                      *duet.terminal.get()*
    Return the session with id {id} (see `b:duet_session`), or `nil`.

require("duet.terminal").list()                        *duet.terminal.list()*
    Return all sessions, most recently used first.

require("duet.terminal").ensure([{agent}] [, {opts}]) *duet.terminal.ensure()*
    Return the running session for the current project, starting the agent
    if there is none and restarting it if it has exited, or `nil` and an
    error message. The cursor does not move. With `{ show = true }`, a
    session this call starts is shown. As with |:Duet-open|, an agent that
    exited while you were not looking is not restarted: its terminal is
    shown, so you can read its output, and an error is returned; the next
    call restarts it.

                                                     *duet-session-when_ready*
session:when_ready({timeout_ms}, {cb})
    Call {cb} once the agent accepts input, as its adapter's `is_ready`
    tells from the terminal's last lines (an adapter without `is_ready` is
    ready whenever the agent runs). Checked afresh on every call, so a
    dialog the agent shows makes it wait. {cb} gets an error message if the
    agent is not ready after {timeout_ms} milliseconds, or exits or is
    stopped first. `session:is_ready()` answers the same question now.

                                                          *duet-session-input*
session:input()
    What the agent's input box holds now, as its adapter's `read_input`
    reads it from the terminal's last lines, or `nil` if no input box is on
    screen or the adapter has no `read_input`. Returns `nil` and an error
    message if the agent is gone or `read_input` failed.

                                                           *duet-session-poll*
session:poll({timeout_ms}, {check}, {cb})
    Call {check} now and then every 50 ms, without blocking, until it
    returns `true` or `nil, err`, then call {cb} with that error (or none).
    After {timeout_ms} milliseconds, {cb} gets `nil, true` (timed out)
    instead. |duet-session-when_ready| is built on it.

10. SENDING TEXT                                                   *duet-send*

|:Duet-send|, |:Duet-prompt| and |duet.send()| type text into the agent's
terminal. Agents take a newline as "submit", so duet writes the text as one
bracketed paste (`ESC [200~` ... `ESC [201~`) and then presses <Enter>
after |duet-config-send-submit_delay_ms|. Multi-line text arrives as one
message and is submitted once.

Before sending, duet removes control characters that could break the
agent's input or end the paste early: every control character except
newline and tab (escape included), DEL and the C1 controls. Line endings
become newlines.

Long text is written in chunks, one per event loop turn, so Neovim stays
responsive. Texts sent to the same agent arrive in the order they were
sent, each one whole. Don't type in the agent's terminal while a send is
running: your keys could end up in the text, or be submitted with it.

The text is typed as it is, so the agent reads it as if you had typed it:
for Claude Code, text starting with `/` runs that command, and text
starting with `!` runs in its shell mode. Typing `/` opens Claude Code's
command menu, and <Enter> runs the entry it highlights rather than exactly
what was typed. Send a command's full name (`/clear`, `/compact keep the
tests`): Claude Code highlights an exact match, while a prefix such as
`/co` runs the first match (`/copy`).

Each send waits until the agent is ready for input: its input prompt is on
screen, not a dialog (see |duet-config-send-ready_timeout_ms|). Text never
goes into a dialog, such as a permission prompt, where <Enter> would answer
it. If the agent's terminal is hidden while it asks something, duet shows
it, without moving the cursor.

If a dialog opens after the paste but before <Enter>, the text is left in
the agent's input without being submitted, and duet tells you and shows the
terminal. Texts sent after it and still waiting are dropped: pasted after
it, they would be submitted together with it. duet waits a moment before it
decides a dialog opened, since the input prompt can leave the screen
briefly while the agent redraws.

An agent can be slow to take text in, as Claude Code is while it starts.
When the adapter can read the agent's input box (`read_input` in
|duet-agents-adapter|; Claude Code's can), duet presses <Enter> only once
the paste shows in the box, and starts the next send only once the box has
changed after <Enter>, so texts sent back to back run as separate messages
instead of merging into one. If the box doesn't change within a couple of
seconds, duet goes on anyway.

If the agent is not running, duet starts it and shows its terminal without
moving the cursor. A first start in a new folder may ask you something
first, such as whether you trust the folder: answer it in the terminal,
then send again if the send timed out. If the agent exited while its
terminal was hidden, duet shows that terminal instead of restarting the
agent, so its last output isn't lost; send again to restart it.

11. CONTEXT AND PROMPTS                                         *duet-context*

Text sent with |:Duet-send|, |:Duet-prompt| and |:Duet-ask| can hold
placeholders, which are replaced with context from the editor when the
command runs. |duet.send()| sends text as it is, without replacing anything.

                                                      *duet-context-providers*
Placeholder       Replaced with ~
`{file}`          A reference to the current file, e.g. `@src/main.lua`.
`{this}`          A reference to the range, or to the cursor line, e.g.
                  `@src/main.lua (lines 10-20)`.
`{selection}`     The range as a fenced code block in the file's language,
                  below its `path:L10-L20` location.
`{diagnostics}`   The current buffer's diagnostics, or those in the range,
                  one `path:line: [SEVERITY] message` line each. A
                  diagnostic is in the range if it is on one of its lines
                  as Neovim counts them (|vim.diagnostic.get()| with
                  `lnum`).
`{diagnostics_all}` The diagnostics of every buffer.
`{quickfix}`      The quickfix list, one `path:line:col: text` line each.
`{buffers}`       A reference to each listed file buffer, one per line.

References are written the way the agent understands them (see
`format_ref` in |duet-agents-adapter|); the examples are Claude Code's.
Paths are relative to the project root (|duet-terminal|), or absolute for
files outside it. Diagnostics are sorted with errors first; the quickfix
list and buffers keep their order. Lists hold at most 200 items, followed by
"… and N more".

A range given to the command (`:'<,'>`, `:3,5`) is whole lines, as for any
Ex command: Vim can't tell a range made by a selection from one you typed.
For the exact text of a character-wise or block-wise selection, run the
command from visual or Select mode with a `<Cmd>` mapping, or call
|duet.ask()| from a mapping (see |duet-context-mappings|); the mode ends
afterwards. A block made with `$` takes each line to its end; a line that
ends before the block is sent empty. Run
from the agent's terminal, the commands use the code window you were in
before, without a range.

How placeholders are replaced:
- Only the names above (and those you add, |duet.context.register()|) are
  placeholders. Other braces, such as `{foo}` or code, are sent as typed.
  There is no way to send a placeholder's name itself through these
  commands; use |duet.send()| for that.
- A placeholder with nothing to add (`{selection}` without a range, no
  diagnostics) becomes empty, and a line it leaves blank is dropped. If
  every placeholder in the text is empty, nothing is sent and duet says
  why.
- A placeholder whose provider fails becomes empty too, and duet shows the
  error: as the reason nothing was sent, or as a warning when the rest of
  the text is sent.
- Code blocks and lists go on lines of their own, so
  `Refactor {selection}` sends "Refactor" with the block below it.
- Text that replaces a placeholder is not searched for placeholders.
- Text right after an empty placeholder stays, punctuation included, so
  put a placeholder that may be empty at the end of a sentence or on a
  line of its own: `{diagnostics_all}, then {file}` starts with a comma
  when there are no diagnostics.

                                                       *duet-context-ctx*
A provider gets a context table: `buf`, `win`, `cursor` (`{ line, col }`,
line 1-based, col 0-based), `cwd` (the project root), `agent` (the adapter)
and `range` (`nil`, or `{ start_line, end_line, mode }` with `mode` one of
`"line"`, `"char"` and `"block"`, plus `start_col` and `end_col` for the
last two: 1-based byte columns of the selection's ends, on `start_line` and
`end_line`. For a block they are its two corners, which getregion() turns
into screen columns, and `to_end` is `true` for a block made with `$`).

                                                       *duet-context-mappings*
Mappings, for example: >lua
    -- Visual mode: send the exact selection with a question you type.
    vim.keymap.set("x", "<leader>as", "<Cmd>Duet prompt {selection}<CR>")
    -- Explain the selection, or the cursor line in normal mode.
    vim.keymap.set({ "n", "x" }, "<leader>ae", function()
      require("duet").ask("explain")
    end)
    -- Fix the diagnostics in the selection, or in the buffer.
    vim.keymap.set({ "n", "x" }, "<leader>af", function()
      require("duet").ask("fix")
    end)
    -- Pick a prompt.
    vim.keymap.set({ "n", "x" }, "<leader>ap", ":Duet ask<CR>")
<

12. FILE LINKS                                                    *duet-links*

Agents point at code as `path:line`. In the agent's terminal, in normal
mode, `gf` or <CR> on such a reference opens the file there, and `]l` and
`[l` move the cursor to the next or previous one on screen. CTRL-click on one
opens it in terminal mode too (|duet-links-mouse|). See
|duet-config-terminal-keys| to change the keys.

References duet recognizes ~
    `lua/duet/init.lua:10`          line
    `lua/duet/init.lua:10:5`        line and column
    `init.lua:10-20`  `a.lua:L10-L20`  range
    `a.lua#L10`  `a.lua#L10-L20`  `a.lua#L10C5`
    `@lua/duet/init.lua`  `@a.lua (lines 10-20)`  as duet sends them
    `` `Makefile` ``                  any name in backticks
    `a.lua:12:text`  `a.lua:12:5:text`  grep and ripgrep matches
    `a.lua-12-text`                 their context lines (`-C`)
    `File "a.py", line 10`          Python tracebacks
    `file:///abs/a.lua#L3`          file URIs
Paths may be relative, absolute or start with `~`. They can be surrounded
by brackets, quotes or punctuation, as in `Read(a.lua)`, `(see a.lua:3).`
or compiler output (`./a.go:12:3: …`). Without a line number, a word
counts only if it has a `/` or an extension, starts with `@`, or is in
backticks. URLs other than `file://` are not file links.

Hyphens are common in file names, so a context line counts only when the
whole word is not a file and the part before `-12-` is one that exists, with
a `/` or an extension: `my-file-12-notes.md` stays a name.

A reference that wraps at the terminal's width, whether the terminal wraps
it or the agent's TUI does (Claude Code indents what follows), is still one
link: `gf` works on either half. duet joins a row that fills the width with
the next row, without its indent, and keeps the joined reference only when
it names a file that exists. An indented row is the TUI's: it wraps at
spaces, so it is joined only for a reference too long to fit on a row.

A relative path is looked up in the session's project root (|duet-terminal|),
then in the git root that contains it. A reference to a file that does not
exist is not a link: `gf` on it shows a message, and `]l` and `[l` skip it.
A directory opens in whatever handles directories (|netrw|, a file
explorer plugin).

Where the file opens: in the current window if it shows a file (as when
|duet.links.open()| is called from one), else the previous window if it does,
else the first window in the tab that does. A window is skipped, unless it
already shows the file, when its buffer can't change: it sets 'winfixbuf', or
its buffer is modified and |:edit| would refuse to leave it (E37): the buffer
is in no other window, and neither 'bufhidden' set to "hide", 'hidden' (when
'bufhidden' is empty) nor 'autowriteall' lets it go. (|duet-context|'s
`{file}` still refers to a skipped window.) A floating terminal is hidden
first, so the file isn't behind it. With no such window, the file replaces a
start screen, as |:edit| would: a window whose filetype is in
|duet-config-links-replace_filetypes| (the snacks, alpha, dashboard-nvim,
mini.starter and startify dashboards by default), unless the buffer is
modified or a terminal, or the window is floating or sets 'winfixbuf'. The
current window is preferred, then the previous one, then the widest (and of
those, the tallest). Sidebars such as file explorers have other filetypes and
are never used. With no such window either, a split opens on the other side of
the terminal. The cursor goes to the line (and column), the view is centered,
and the line or range flashes with |hl-DuetLinkFlash|. The jump is added to
the |jumplist|, so CTRL-O goes back.

Opening a link with the mouse ~
                                                            *duet-links-mouse*
CTRL-click (`<C-LeftMouse>`) on a link in the agent's terminal opens it, as
`gf` does, without leaving |Terminal-mode| first. It also works in normal
mode, and when the agent uses the mouse itself: duet gets the CTRL-click
before the agent does, and a plain click still goes to the agent. A
CTRL-click on text in the terminal that is not a link, or names a file that
does not exist, does nothing: until the button is let go, duet also keeps
the click's drag and release (`<C-LeftDrag>`, `<C-LeftRelease>`, and
`<LeftDrag>`, `<LeftRelease>` for when CTRL is let go first), except keys you
map in |duet-config-terminal-keys|. A double or triple click on the
terminal's text acts once: duet keeps its next presses (`<2-C-LeftMouse>`,
…) with their drags and releases, so they don't reach the agent, unless
you map them.

Anywhere else, such as another window or a status line, the click does what
it does without duet: your own global mapping of the key (for example
`<C-LeftMouse>` for LSP go-to-definition), else Neovim's built-in action, with
the register and count typed before it in normal mode. As Neovim does, in
|Terminal-mode| with no Terminal-mode mapping of the key, the click leaves
Terminal mode and gets your normal mode mapping. Only a click in a window
showing the agent's terminal while that terminal is the current buffer is
seen: from another window, it is Neovim's own CTRL-click.

The terminal gets clicks only when 'mouse' has the `n` or `a` flag (the
default "nvi" does): Neovim reads them in |Terminal-mode| as in normal mode.
|duet-health| warns when it has neither. The click must also get past the terminal
emulator Neovim runs in, and many keep some modified clicks for themselves.
Map another key with the `"open_link_mouse"` action if yours does: >lua
    terminal = { keys = {
      ["<C-LeftMouse>"] = false,
      ["<C-M-LeftMouse>"] = "open_link_mouse",
    } }
<
Known quirks:
- CMD-click (macOS) can't work: the mouse protocol has no bit for it, and
  Ghostty, iTerm2, kitty and WezTerm use it to open URLs themselves.
- CTRL-click is a right-click by macOS convention: some terminals, such as
  Terminal.app, show a context menu or send a right click instead. Try
  `<C-M-LeftMouse>` there.
- ALT/OPTION-click moves the shell cursor in some terminals (Ghostty's
  `cursor-click-to-move`, iTerm2, Terminal.app), so `<M-LeftMouse>` is a poor
  choice on macOS unless you turn that off.
- SHIFT-click is kept by most terminals for selecting text while a program
  uses the mouse, so `<S-LeftMouse>` rarely reaches Neovim.
- In tmux, clicks reach Neovim only with `set -g mouse on`; tmux passes the
  modifiers on.
- Neovim counts clicks at the same place whatever the modifiers: a CTRL-click
  right after a plain click there (within 'mousetime') is `<2-C-LeftMouse>`,
  a different key. Map it too if you click to focus first.

OSC 8 hyperlinks ~
Programs can print a link whose target differs from its text, as OSC 8
hyperlinks; Claude Code does so for markdown links and URLs when it detects
a terminal that supports them. duet records the hyperlinks the agent prints
(Neovim reports them with |TermRequest|) and `gf` on one opens its target
when that is a file: a `file://` URI or a path, with `#L10` for a line. Once
the agent writes over a hyperlink's text, for example when its screen
redraws or the window is resized, duet falls back to the text under the
cursor. If the agent redraws the same text without the hyperlink, duet can't
tell, and `gf` there still opens the old target.

Claude Code detects hyperlink support from the environment, which the agent's
terminal inherits from Neovim's (e.g. `$TERM_PROGRAM` of the terminal Neovim
runs in). To turn it on or off regardless: >lua
    agents = { claude = { env = { FORCE_HYPERLINK = "1" } } }  -- "0": off
<

Limits: a reference that wraps over more than two rows is not recognized.
A line that fills the terminal's width exactly looks the same as one that
wraps, so a reference at its end is joined with a next line that goes on
it, e.g. digits that extend its line number.
Paths with spaces are only recognized as OSC 8 targets or `file://` URIs
(with `%20`).

                                                                 *hl-DuetLink*
DuetLink          Links underlined with |duet-config-links-highlight|.
                  Linked to |hl-Underlined|.
                                                            *hl-DuetLinkFlash*
DuetLinkFlash     The line or range briefly highlighted when a link opens.
                  Linked to |hl-IncSearch|.

Lua API ~
                                                          *duet.links.parse()*
require("duet.links").parse({line}, {opts})
    The file references in the string {line}, without checking the files:
    a list of `{ path, line?, end_line?, col?, s, e }`, where `s` and `e`
    are the 1-based byte columns of the reference (inclusive). With
    `opts.exists`, a function that tells whether a path is a file, grep
    context lines are recognized too.

                                                           *duet.links.find()*
require("duet.links").find({lines}, {opts})
    The links in the list of rows {lines} that resolve, joining references
    wrapped from one row to the next. {opts} has `resolve`, a function from
    a path to its absolute path or `nil`; `is_file`, whether such an
    absolute path is a regular file (default: asks the filesystem), for
    grep context lines; `width`, the terminal's width in
    cells (no rows are joined without it); and `first`, the buffer row of
    the first line (default 1). Each link also has `row` and `abs`, and a
    wrapped one `tail = { row, s, e }`, its part on the next row.

                                                        *duet.links.resolve()*
require("duet.links").resolve({path}, {cwd})
    The absolute path {path} refers to, looked up as described above from
    {cwd} (default: the current directory), or `nil` and an error.

                                                       *duet.links.resolver()*
require("duet.links").resolver({cwd})
    A function that does what |duet.links.resolve()| does for many paths
    from one {cwd}, finding its git root once.

                                                             *duet.links.at()*
require("duet.links").at({win}, {row}, {col})
    The link at the 1-based {row} and byte column {col} of window {win},
    resolved: an OSC 8 hyperlink there first, then a reference. Returns the
    link, or `nil` and the reason.

                                                           *duet.links.open()*
require("duet.links").open({link}, {opts})
    Open a link (a table with `path` and optionally `line`, `end_line`,
    `col`) as `gf` does. A relative `path` is resolved from `opts.cwd`
    (default: the project root). Returns `true`, or `nil` and an error.

13. RELOADING CHANGED FILES                                       *duet-watch*

The agent edits files on disk. While an agent session runs, duet watches
the directory of every listed file buffer and, once the changes stop for
|duet-config-watch-debounce_ms|, runs |:checktime| for the buffers in the
directories that changed. Buffers without unsaved changes reload (with
'autoread', which duet turns on while watching: see
|duet-config-watch-autoread|). A buffer with unsaved changes is never
overwritten: Neovim asks what to do, as for any file changed outside it
(|W12|). An agent that writes the same file several times asks again
after each write.

So that a key you type does not answer that question, a buffer that would
ask (unsaved changes, a file created since or deleted, or 'autoread' off)
is not checked while you type: in
the agent's terminal, Insert or Replace mode, or after an operator. It is
checked when the mode changes, e.g. when you leave terminal mode. Buffers
that reload without asking are checked at once. Any check that would land
while the command line, its window or a prompt is open waits until it is
closed. A check that fails, e.g. because of an error in a |FileChangedShell|
autocommand, is reported and not retried until the file changes again.

duet also checks the watched buffers when you leave the agent's terminal
mode (|TermLeave|) and when Neovim gains focus (|FocusGained|), so a change
the watchers missed shows up there.

Watching starts with the first running session and stops when the last one
stops or exits; then every watcher is closed and 'autoread' is put back.
Directories are watched rather than files, so files written by renaming a
temporary file over them are noticed too. When the agent creates the file
of a buffer you opened before it existed, Neovim tells you (|W13|) and
offers to load it, as with |:checktime| by hand. A watched directory that
is removed and created again, as some generators do, is watched again. A
directory that does not exist (yet) is looked for once a second, and
watched from when it appears. Buffers that are not files (terminals,
`duet://`, `oil://`, other URIs) are not watched. Turn watching off with: >lua
    watch = { enabled = false }
<
Neovim 0.13 and later watch the files of 'autoread' buffers themselves
(see `:help 'autoread'` there). duet then leaves the watching to Neovim and
only turns 'autoread' on while a session runs (|duet-config-watch-autoread|);
what is described above about checks waiting while you type does not apply.

On Linux each directory uses one inotify watch. If the system limit
(`fs.inotify.max_user_watches`) is reached, duet logs it once and the
directory is only checked on |TermLeave| and |FocusGained| until watching
starts again.

 vim:tw=78:ts=8:noet:ft=help:norl:
